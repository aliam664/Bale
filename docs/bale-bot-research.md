## ۰. خلاصهٔ مدیریتی

| پرسش | پاسخ کوتاه |
|---|---|
| ربات بله چطور ساخته می‌شود؟ | از `@botfather` داخل بله توکن می‌گیرید و با HTTP به `https://tapi.bale.ai/bot<TOKEN>/<METHOD>` درخواست می‌زنید. |
| API بله شبیه چیست؟ | **کپی API ربات تلگرام با تغییرات جزئی.** اکثر کتابخانه‌های تلگرام با عوض‌کردن آدرس پایه کار می‌کنند. |
| می‌شود سرور روی کامپیوتر شخصی باشد؟ | **بله.** با روش **Long Polling** (`getUpdates`) نیازی به IP عمومی، دامنه یا SSL نیست. Webhook فقط با HTTPS عمومی روی پورت ۴۴۳ یا ۸۸ کار می‌کند. |
| ابزار لازم برای بازی دوز وجود دارد؟ | **بله.** دکمه‌های شیشه‌ای (inline keyboard)، `callback_query`، ویرایش پیام (`editMessageText`) و `answerCallbackQuery` همگی پشتیبانی می‌شوند. |
| مچ‌میکینگ دو کاربر ممکن است؟ | **بله.** هر کاربر در چت خصوصی خودش با ربات است؛ ربات دو نفر را در صف نگه می‌دارد، جفت می‌کند و هر حرکت را با ویرایش پیامِ تختهٔ هر دو نفر منعکس می‌کند. (نمونهٔ مشابه: ربات «چت ناشناس» با Balethon.) |
| بازی با کامپیوتر؟ | کاملاً سمت سرور شماست؛ الگوریتم Minimax برای دوز، حریفی شکست‌ناپذیر می‌سازد. |
| پیشنهاد فنی | Python + کلاینت سبک روی HTTP API (یا `python-telegram-bot` با `base_url`، یا کتابخانهٔ بومی `Balethon`). نمونهٔ اولیهٔ کارکرده با تست در همین مخزن (`bot/`) قرار دارد. |
| ریسک اصلی | جزئیات تأییدنشدهٔ سازگاری با تلگرام؛ `answerCallbackQuery` فقط در کلاینت‌های جدید؛ قالب‌بندی خودکار Markdown؛ نگهداری فقط ۲۰۰۰ آپدیت آخر برای ۲۴ ساعت. |

## ۱. بله و «بازو» چیست؟

- **بله** پیام‌رسان ایرانی است و به ربات‌ها در آن **«بازو»** گفته می‌شود. صفحهٔ توسعه‌دهندگان بله از «جامعهٔ ۶۰ میلیونی کاربران»، «۳۰+ هزار ربات فعال»، «منطبق بر APIهای تلگرام» و «دارای API پرداخت» صحبت می‌کند. [[bale.ai/dev]](https://bale.ai/dev)
- مستندات رسمی: <https://docs.bale.ai> (و مستندات مینی‌اپ در <https://docs.bale.ai/miniapp>). پرتال توسعه‌دهندگان: <https://dev.bale.ai>.
- جملهٔ کلیدی مستندات رسمی: *«API بازوی بله بر پایهٔ API بات تلگرام و با اعمال تغییراتی جزئی طراحی شده است؛ بنابراین می‌توانید از کتابخانه‌های متعددی که برای توسعهٔ بات تلگرام در زبان‌های مختلف ارائه شده‌اند، برای ساخت بازو در بله نیز استفاده کنید.»* [[docs.bale.ai]](https://docs.bale.ai/)
- پشتیبانی توسعه‌دهندگان: بخش «بازو» در `@supportbot` داخل بله.

## ۲. ساخت بازو قدم‌به‌قدم

1. در بله، `@botfather` را باز کنید (<https://ble.ir/botfather>) → «شروع» → «ساخت بازوی جدید».
2. یک **نام نمایشی** (مثلاً «دوز آنلاین») و یک **نام کاربری** که به `bot` ختم شود (مثلاً `@mydoozbot`) انتخاب کنید.
3. بات‌فادر یک **توکن** با قالبی شبیه `123456789:abcdIuZmK5qNEm2A1BhUaAg7MPJv1O9KCcBQB2ro` می‌دهد. این توکن رمز ربات شماست؛ هرگز در کد/گیت قرار ندهید (از فایل `.env` استفاده کنید). اگر گم شد، در بات‌فادر می‌توانید توکن قبلی را باطل و توکن جدید بگیرید. [[bale.ai/dev]](https://bale.ai/dev)
4. تست سریع در مرورگر یا `curl`:

   ```bash
   curl https://tapi.bale.ai/bot<TOKEN>/getMe
   # {"ok":true,"result":{"id":...,"is_bot":true,"first_name":"...","username":"..."}}
   ```

5. (اختیاری) در بات‌فادر: توضیحات ربات، توکن پرداخت کیف‌پولی، فعال‌سازی مینی‌اپ اصلی و تغییر عملکرد دکمهٔ منو را می‌توان تنظیم کرد.
6. لینک ربات: `https://ble.ir/<bot_username>`؛ با پارامتر شروع: `ble.ir/<bot_username>?start=<parameter>` → برای کاربر پیام `/start <parameter>` ارسال می‌شود (مناسب «لینک دعوت دوست به بازی»). [[docs.bale.ai]](https://docs.bale.ai/)

## ۳. ساختار API بازوی بله

| مورد | مقدار |
|---|---|
| آدرس پایه | `https://tapi.bale.ai/bot<token>/METHOD_NAME` |
| دانلود فایل | `https://tapi.bale.ai/file/bot<token>/<file_path>` |
| API کسب‌وکاری (پولی، نرخ بالاتر) | `https://tapi.bale.ai/business/bot<TOKEN>/<METHOD>` |
| متدهای HTTP | `GET` و `POST` |
| روش ارسال پارامتر | query string، `application/x-www-form-urlencoded`، `application/json` (به‌جز آپلود فایل)، `multipart/form-data` (برای فایل) |
| قالب پاسخ | JSON با فیلد `ok`؛ اگر `true`: نتیجه در `result`؛ اگر `false`: `error_code` و `description` و احتمالاً `parameters.retry_after` |
| حساسیت به حروف | نام متدها حساس به بزرگی/کوچکی نیستند؛ همه‌چیز UTF-8 |

نمونهٔ ارسال پیام با JSON:

```bash
curl -X POST "https://tapi.bale.ai/bot<TOKEN>/sendMessage" \
  -H "Content-Type: application/json" \
  -d '{"chat_id": 123456789, "text": "سلام!",
       "reply_markup": {"inline_keyboard": [[{"text": "شروع بازی", "callback_data": "menu:human"}]]}}'
```

**نکتهٔ مهم: قالب‌بندی متن.** طبق مستندات، *«متن تمامی پیام‌های ارسالی در بله به شکل Markdown قالب‌بندی می‌شوند»* — یعنی پارامتر `parse_mode` معنی ندارد و Markdown همیشه فعال است: `*برجسته*`، `_کج_`، `[متن](لینک)` و «نمایش آنی/اسپویلر» با ```` ```[متن]توضیح``` ````. باید قبل و بعد از ستاره/زیرخط فاصله باشد. پیامد عملی: اگر نام کاربر شامل `_` یا `*` باشد، ممکن است متن به‌هم بریزد؛ متن‌های کاربر را پاک‌سازی کنید. [[docs.bale.ai]](https://docs.bale.ai/)

## ۴. دریافت آپدیت‌ها: Polling یا Webhook؟

ربات باید رویدادها (پیام، کلیک دکمه و…) را از سرور بله بگیرد. دو روش رسمی وجود دارد و در هر دو، آپدیت‌ها شیء JSON یکسانی هستند. آپدیت‌های دریافت‌نشده روی سرور می‌مانند: **«در حال حاضر ۲۰۰۰ پیام آخر به مدت ۲۴ ساعت نگهداری می‌شود.»** [[docs.bale.ai]](https://docs.bale.ai/)

### ۴.۱ شیء Update

| فیلد | توضیح |
|---|---|
| `update_id` | شناسهٔ یکتا و صعودی |
| `message` | پیام جدید (متن، عکس، …) |
| `edited_message` | پیام ویرایش‌شده |
| `callback_query` | کلیک روی دکمهٔ شیشه‌ای (inline) — **قلب ربات بازی** |
| `pre_checkout_query` | مربوط به پرداخت |

در هر آپدیت حداکثر یکی از فیلدهای اختیاری پر است.

### ۴.2 getUpdates (Long Polling) — پیشنهاد برای «سرور روی سیستم شخصی»

```
POST /getUpdates  {"offset": <last_update_id + 1>, "limit": 100, "timeout": 30}
```

- `offset`: یک واحد بیشتر از بزرگ‌ترین `update_id` دریافتی قبلی؛ با این کار آپدیت‌های قبلی «تأییدشده» تلقی و حذف می‌شوند.
- `limit`: ۱ تا ۱۰۰ (پیش‌فرض ۱۰۰).
- `timeout`: مدت انتظار Long Polling (ثانیه)؛ تعداد درخواست‌ها را کم و کارایی را بهتر می‌کند.
- مزیت: **اتصال خروجی** از سمت شماست؛ نیازی به IP عمومی، دامنه، SSL یا باز کردن پورت نیست. پشت NAT/مودم خانگی کار می‌کند.
- اگر قبلاً Webhook ست شده باشد، ابتدا `deleteWebhook` را فراخوانی کنید.

### ۴.۳ Webhook

- `setWebhook(url)` با آدرس HTTPS؛ بله آپدیت‌ها را با `POST` به آن می‌فرستد. **پورت‌های پشتیبانی‌شده فقط ۴۴۳ و ۸۸.** `deleteWebhook` و `getWebhookInfo` هم وجود دارند.
- نیازمند سرور با آدرس عمومی و گواهی SSL معتبر است → برای سیستم شخصی مناسب نیست (مگر با تونل‌هایی مثل ngrok که پایدار نیستند).

### ۴.۴ مقایسه

| معیار | Long Polling | Webhook |
|---|---|---|
| نیاز به IP/دامنهٔ عمومی | خیر | بله (HTTPS، پورت ۴۴۳/۸۸) |
| اجرا روی PC خانگی | ✅ | ❌ (عملاً) |
| تأخیر | ~صفر تا چند صد میلی‌ثانیه | کمترین |
| پیچیدگی | کم | متوسط (وب‌سرور + SSL) |
| مقیاس‌پذیری | برای ربات کوچک/متوسط کافی | بهتر در مقیاس بزرگ |

**نتیجه:** برای ایدهٔ شما، Long Polling انتخاب درست است.

## ۵. اشیا و متدهای کلیدی برای یک ربات بازی

### ۵.۱ اشیای پایه

- **User**: `id`, `is_bot`, `first_name`, `last_name?`, `username?`, `language_code?`
- **Chat**: `id`, `type` (`private` / `group` / `channel`), `title?`, `username?`, `first_name?`, `last_name?`
- **Message**: `message_id`, `from`, `date`, `chat`, `text`, `entities` (فقط `mention` و `bot_command`)، رسانه‌ها، `reply_to_message`, `reply_markup`, `web_app_data` و…
- **CallbackQuery**: `id`, `from`, `message?`, `data?`

### ۵.۲ صفحه‌کلیدها

**InlineKeyboardMarkup** (دکمهٔ شیشه‌ای زیر پیام — برای تختهٔ بازی):

```json
{"inline_keyboard": [
  [{"text": "⬜", "callback_data": "mv:42:0"}, {"text": "❌", "callback_data": "mv:42:1"}, {"text": "⬜", "callback_data": "mv:42:2"}],
  [{"text": "⬜", "callback_data": "mv:42:3"}, {"text": "⭕", "callback_data": "mv:42:4"}, {"text": "⬜", "callback_data": "mv:42:5"}],
  [{"text": "⬜", "callback_data": "mv:42:6"}, {"text": "⬜", "callback_data": "mv:42:7"}, {"text": "⬜", "callback_data": "mv:42:8"}],
  [{"text": "🏳️ تسلیم", "callback_data": "g:resign:42"}]
]}
```

- **InlineKeyboardButton**: `text` + فقط یکی از `url` | `callback_data` (**۱ تا ۶۴ بایت**) | `web_app` | `copy_text`.
- **ReplyKeyboardMarkup / KeyboardButton** (صفحه‌کلید پایین صفحه): `text`, `request_contact`, `request_location`, `web_app`؛ و **ReplyKeyboardRemove** برای حذف.

### ۵.۳ متدهای ضروری

| متد | کاربرد در ربات بازی |
|---|---|
| `getMe` | تست توکن |
| `getUpdates` / `setWebhook` / `deleteWebhook` / `getWebhookInfo` | دریافت رویدادها |
| `sendMessage(chat_id, text[1..4096], reply_to_message_id?, reply_markup?)` | منو، پیام «در انتظار حریف»، تختهٔ اولیه |
| `editMessageText(chat_id, message_id, text, reply_markup?)` | **به‌روزرسانی تخته در جا** بعد از هر حرکت (بدون شلوغ‌کردن چت) |
| `editMessageReplyMarkup(chat_id, message_id, reply_markup?)` | فقط تغییر دکمه‌ها |
| `answerCallbackQuery(callback_query_id, text?[0..200], show_alert?)` | خارج‌کردن دکمه از حالت انتظار + نمایش اعلان («نوبت شما نیست!») |
| `deleteMessage(chat_id, message_id)` | پاک‌کردن پیام‌های موقت (فقط تا ۴۸ ساعت) |
| `sendChatAction(chat_id, action)` | نمایش «در حال نوشتن…» (مثلاً وقتی کامپیوتر «فکر می‌کند») |
| `sendPhoto/sendDocument/...` | اختیاری: تصویر تخته |
| `getChat`, `getChatMember`, `banChatMember`, … | مدیریت گروه (در این پروژه لازم نیست) |
| `sendInvoice`, `createInvoiceLink`, `answerPreCheckoutQuery`, `inquireTransaction` | پرداخت کیف‌پولی (برای آینده: سکه/امتیاز) |
| `askReview(user_id, delay_seconds)` | درخواست امتیازدهی به ربات (فقط کلاینت‌های جدید؛ از آبان ۱۴۰۴) |

### ۵.۴ نکتهٔ حیاتی دربارهٔ `answerCallbackQuery`

مستندات: *«پس از فشرده‌شدن یک دکمهٔ اینلاین توسط کاربر، دکمه وارد حالت انتظار و تا زمان فراخوانی متد answerCallbackQuery در این حالت باقی می‌ماند. بنابراین لازم است این متد را حتی در صورتی که نیازی به نمایش پیامی ندارید فراخوانی کنید.»*

و: *«این قابلیت از خرداد ۱۴۰۴ به کلاینت‌های بله افزوده شده و در نسخه‌های قدیمی در دسترس نیست؛ اگر `callback_query_id` با `1` آغاز شود، کاربر از نسخهٔ قدیمی استفاده می‌کند.»* در این حالت باید بازخورد را با پیام معمولی بدهید. [[docs.bale.ai]](https://docs.bale.ai/)

→ در کد: همیشه `answerCallbackQuery` را صدا بزنید، خطای آن را نادیده بگیرید، و برای idهایی که با `1` شروع می‌شوند پیام جایگزین بفرستید.

### ۵.۵ فایل‌ها (در صورت نیاز)

- سه روش ارسال: `file_id` (بدون محدودیت)، URL (عکس ≤ ۵MB، بقیه ≤ ۲۰MB)، آپلود multipart (عکس ≤ ۱۰MB، بقیه ≤ ۵۰MB).
- `getFile` فقط تا ۲۰MB؛ لینک دانلود یک ساعت معتبر است.

## ۶. تفاوت‌ها با تلگرام و محدودیت‌های مهم

| موضوع | وضعیت در بله | پیامد برای پروژه |
|---|---|---|
| Inline mode (`inline_query`، `@bot` در هر چت) | **در مستندات وجود ندارد** | نمی‌توان مثل تلگرام بازی را داخل چت دو کاربر «اینلاین» اجرا کرد؛ بازی در چت خصوصی هر نفر با ربات انجام می‌شود (همان ایدهٔ شما). |
| Telegram Games API (`sendGame`, HTML5 games) | وجود ندارد | جایگزین: دکمه‌های شیشه‌ای یا **مینی‌اپ** (بخش ۱۰). |
| `parse_mode` | وجود ندارد؛ Markdown همیشه فعال | پاک‌سازی ورودی کاربر؛ فاصله قبل/بعد از `*` و `_`. |
| `MessageEntity` | فقط `mention` و `bot_command` | — |
| آپدیت‌های `poll`, `chat_member`, `my_chat_member`, `inline_query`, `chosen_inline_result` | در لیست Update نیستند | — |
| `callback_data` | ۱ تا ۶۴ بایت | فرمت فشرده مثل `mv:<game_id>:<cell>` |
| `answerCallbackQuery` | فقط کلاینت‌های جدید (خرداد ۱۴۰۴ به بعد) | fallback با پیام |
| Webhook | فقط پورت ۴۴۳ و ۸۸ | Polling برای PC |
| نگهداری آپدیت | ۲۰۰۰ آپدیت آخر، ۲۴ ساعت | اگر ربات بیش از ۲۴ ساعت خاموش باشد، پیام‌ها از دست می‌روند |
| Rate Limit | «تعاملی» (بر اساس میزان تعامل کاربران با بازو در چت خصوصی)؛ عدد دقیقی اعلام نشده؛ پاسخ خطا ممکن است `retry_after` داشته باشد | پیاده‌سازی backoff؛ برای پیام انبوه/اطلاع‌رسانی خارج از گفتگو، API کسب‌وکاری پولی (`/business/`) با متدهای محدود (`getMe, sendMessage, forwardMessage, sendPhoto, sendVideo, sendAudio, sendDocument`) و فقط برای چت خصوصی و `file_id` |
| `deleteMessage` | فقط پیام‌های کمتر از ۴۸ ساعت | — |
| پرداخت | فقط کیف‌پول بله (کارت‌به‌کارت حذف شده)؛ توکن تست `WALLET-TEST-1111111111111111`؛ واحد ریال؛ پاسخ به `pre_checkout_query` حداکثر ۱۰ ثانیه | برای آینده |
| اندازهٔ شناسه‌ها | `id`ها می‌توانند بزرگ‌تر از ۳۲ بیت باشند (تا ۵۲ بیت معنادار) | در زبان‌هایی مثل JS مراقب باشید؛ در Python مشکلی نیست |
| `setMyCommands` | **در مستندات رسمی نیست** (یک SDK شخص‌ثالث آن را لیست کرده) | تأییدنشده؛ در عمل تست شود |

نمونهٔ حداقلی با PTB (برگرفته از آموزش فارسی Medium، آبان ۱۴۰۴):

```python
from telegram.ext import Application, MessageHandler, filters

async def echo(update, context):
    await update.message.reply_text(update.message.text)

app = (Application.builder()
       .token("TOKEN")
       .base_url("https://tapi.bale.ai/bot")
       .base_file_url("https://tapi.bale.ai/file/bot")
       .build())
app.add_handler(MessageHandler(filters.TEXT, echo))
app.run_polling()
```

## ۸. طراحی پیشنهادی ربات دوز با مچ‌میکینگ

### ۸.۱ جریان کاربری (UX)

```
کاربر ──/start──▶ منوی اصلی (دکمه‌های شیشه‌ای)
                   ├─ 🎮 بازی با حریف آنلاین ─▶ ورود به صف ─▶ «در انتظار حریف… [❌ انصراف]»
                   │                                   │
                   │                 نفر دوم وارد صف شد ┘─▶ جفت‌شدن ─▶ ارسال تخته به هر دو نفر
                   ├─ 🤖 بازی با کامپیوتر ─▶ انتخاب سطح (آسان/متوسط/سخت) ─▶ تخته
                   └─ ❓ راهنما

حین بازی: کلیک روی خانه ─▶ اعتبارسنجی (نوبت؟ خانه خالی؟) ─▶ به‌روزرسانی وضعیت
          ─▶ editMessageText برای *هر دو* بازیکن ─▶ answerCallbackQuery
پایان: برد/مساوی/تسلیم/تایم‌اوت ─▶ تختهٔ نهایی + [🔁 بازی مجدد] [🏠 منو]
```

نکات UX:
- هر بازیکن تختهٔ خودش را در چت خصوصی‌اش می‌بیند؛ متن بالای تخته می‌گوید «نوبت شماست ❌» یا «منتظر حرکت حریف ⭕».
- اگر کاربر در نوبت حریف کلیک کند: `answerCallbackQuery(text="نوبت شما نیست!")`.
- حریف ناشناس بماند یا نام کوچکش نمایش داده شود؟ (پیشنهاد: فقط نام کوچک، بدون username.)
- «بازی مجدد» دو طرفه: وقتی هر دو بزنند، بازی جدید با تعویض نماد.

### ۸.۲ معماری

```
┌──────────────┐   HTTPS (long polling: getUpdates / sendMessage / editMessageText …)
│ سرورهای بله  │◀──────────────────────────────────────────────────────────────┐
└──────────────┘                                                              │
                                                                   ┌──────────┴───────────┐
                                                                   │  پردازهٔ ربات روی PC  │
                                                                   │  (Python asyncio)     │
                                                                   │                       │
                                                                   │  BaleAPI (HTTP client)│
                                                                   │      │                │
                                                                   │  Dispatcher ──▶ Handlers (start / menu / move / resign …)
                                                                   │      │                │
                                                                   │  Matchmaker (صف) ─ GameManager (بازی‌های فعال) ─ AI (Minimax)
                                                                   │      │                │
                                                                   │  Storage: حافظه (شروع) → SQLite (آمار/پایداری)
                                                                   └───────────────────────┘
```

**مدل داده:**

```python
Player: chat_id, name
Game:   id, players {X: chat_id | "cpu", O: chat_id}, board[9], turn, status,
        message_ids {chat_id: message_id}, created_at, last_move_at
Queue:  deque[chat_id]  (+ زمان ورود برای تایم‌اوت)
```

**قرارداد `callback_data` (≤ ۶۴ بایت):**

| داده | معنی |
|---|---|
| `menu:human` / `menu:cpu` / `menu:help` | منوی اصلی |
| `cpu:easy` / `cpu:medium` / `cpu:hard` | سطح کامپیوتر |
| `q:cancel` | انصراف از صف |
| `mv:<game_id>:<0..8>` | حرکت در خانه |
| `g:resign:<game_id>` | تسلیم |
| `g:again:<game_id>` | درخواست بازی مجدد |

**هم‌زمانی:** یک پردازهٔ asyncio که آپدیت‌ها را **به ترتیب** پردازش می‌کند، عملاً از شرایط رقابتی (دو کلیک هم‌زمان) جلوگیری می‌کند. اگر بعداً پردازش موازی خواستید، برای هر بازی یک `asyncio.Lock` بگذارید.

**تایم‌اوت‌ها (با یک تسک پس‌زمینه):** نوبت (مثلاً ۹۰ ثانیه → باخت فنی)، صف (مثلاً ۳ دقیقه → پیشنهاد بازی با کامپیوتر)، بازی‌های رهاشده (پاک‌سازی حافظه).

**هوش مصنوعی دوز:** Minimax کامل (درخت دوز کوچک است؛ بدون نیاز به هرس) → شکست‌ناپذیر. سطوح: آسان = تصادفی، متوسط = ۵۰٪ تصادفی/۵۰٪ بهینه، سخت = همیشه بهینه.

**پایداری:** در نسخهٔ اول وضعیت در حافظه است (با ری‌استارت، بازی‌های جاری از بین می‌روند — قابل قبول). بعداً: SQLite برای آمار برد/باخت و بازیابی بازی‌ها.

**تعمیم به بازی‌های دیگر:** منطق بازی پشت یک رابط ساده (`legal_moves`, `apply`, `status`, `render_keyboard`) قرار می‌گیرد تا بعداً بازی دیگری (مثلاً چهار در یک ردیف، اتللو، دوز ۴×۴) جایگزین شود بدون تغییر مچ‌میکینگ.

### ۸.۳ نمونهٔ اولیهٔ این مخزن

در پوشهٔ `bot/` یک پیاده‌سازی کامل و تست‌شدهٔ همین طراحی (کلاینت HTTP سبک + دوز + مچ‌میکینگ + Minimax) قرار دارد. برای اجرا به `README.md` مراجعه کنید. تست‌ها با یک API جعلی اجرا می‌شوند، بنابراین بدون توکن هم می‌توانید منطق را بررسی کنید؛ تست نهایی باید با توکن واقعی و دو حساب بله انجام شود.

## ۹. اجرای ربات روی سیستم شخصی

- **پیش‌نیازها:** Python 3.10+ (یا Node و…)، اینترنت پایدار. `tapi.bale.ai` داخل شبکهٔ ایران است؛ به VPN نیاز ندارد (و اگر VPN روشن باشد ممکن است مسیر دسترسی تغییر کند).
- **بدون پورت‌فورواردینگ:** چون Polling اتصال خروجی است.
- **فقط یک نمونه از ربات را هم‌زمان اجرا کنید؛** دو پردازهٔ هم‌زمان با `getUpdates` آپدیت‌ها را از هم می‌دزدند.
- **همیشه روشن ماندن:**
  - ویندوز: Task Scheduler (اجرا هنگام ورود + ری‌استارت در خطا) یا NSSM برای سرویس ویندوز.
  - لینوکس: یک unit فایل `systemd` با `Restart=always`.
  - یا Docker با `--restart unless-stopped`.
  - اگر PC به حالت Sleep برود ربات قطع می‌شود؛ تنظیمات برق را بررسی کنید.
- **توکن در `.env`؛** لاگ‌گیری در فایل؛ مدیریت خطای شبکه با تلاش مجدد و backoff؛ احترام به `retry_after`.
- **بعداً:** اگر خواستید ۲۴/۷ و پایدارتر باشد، یک VPS ارزان ایرانی کافی است (همان کد با Polling کار می‌کند؛ یا Webhook با دامنه و SSL).

## ۱۰. گزینهٔ مینی‌اپ برای رابط گرافیکی

بله از **مینی‌اپ** (صفحهٔ وب داخل بله، مشابه Telegram Web Apps) پشتیبانی می‌کند:

- چهار راه باز شدن: مینی‌اپ اصلی (`ble.ir/<bot>?startapp=<param>`)، دکمهٔ منوی بازو، دکمهٔ شیشه‌ای با `web_app`، دکمهٔ صفحه‌کلید با `web_app`.
- اسکریپت `https://tapi.bale.ai/miniapp.js` شیء `window.Bale.WebApp` را می‌سازد: `initData` (باید سمت سرور اعتبارسنجی شود)، `themeParams`, `colorScheme`, `BackButton`, `SettingsButton`, پرداخت با `openInvoice` و….
- راهنمای طراحی: Responsive و mobile-first، توجه به تم تیره/روشن، متن دکمهٔ مینی‌اپ حداکثر ۲۰ کاراکتر در اندروید.
- **اما:** مینی‌اپ باید روی **HTTPS عمومی** میزبانی شود → با فلسفهٔ «سرور روی PC» سازگار نیست مگر این‌که فقط فایل‌های استاتیک را روی یک هاست ارزان بگذارید و منطق بازی را از طریق ربات/یک API عمومی مدیریت کنید. برای فاز اول توصیه نمی‌شود؛ برای بازی‌های گرافیکی‌تر در آینده گزینهٔ خوبی است.

## ۱۱. ریسک‌ها، نکات باز و موارد تأییدنشده

1. **سازگاری «جزئی» با تلگرام** یعنی برخی پارامترها بی‌صدا نادیده گرفته می‌شوند و برخی متدها وجود ندارند. → از همان روز اول با توکن واقعی تست کنید.
2. **کلاینت‌های قدیمی** `answerCallbackQuery` را ندارند (شناسهٔ callback با `1` شروع می‌شود) → بازخورد با پیام.
3. **Markdown خودکار** ممکن است نام کاربران را به‌هم بریزد → پاک‌سازی.
4. **قطع ربات بیش از ۲۴ ساعت** = از دست رفتن آپدیت‌ها؛ **۲۰۰۰ آپدیت** سقف صف است.
5. **Rate limit نامشخص** → backoff و پرهیز از ارسال انبوه؛ ویرایش پیام به‌جای ارسال پیام جدید (برای هر حرکت ۲ ویرایش + ۱ answerCallbackQuery).
6. **ارسال JSON تو در تو برای `reply_markup`** در پروژه‌های جامعه کار کرده است؛ اگر خطا گرفتید، به‌صورت رشتهٔ JSON (`json.dumps`) در فرم بفرستید.
7. **موارد تأییدنشده:** وجود `setMyCommands`؛ رفتار دقیق کلاینت‌ها هنگام ویرایش سریع و پشت‌سرهم پیام؛ حداکثر تعداد دکمه در هر ردیف (۳ تایی برای دوز قطعاً مشکلی ندارد)؛ سازگاری عملی aiogram/grammY.
8. **برابر بودن `chat.id` با `user.id` در چت خصوصی** را فرض نکنید؛ همیشه `chat.id` از پیام `/start` را ذخیره کنید (در نمونهٔ کد همین کار شده است).
